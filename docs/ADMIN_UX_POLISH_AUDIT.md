# ADMIN_UX_POLISH_AUDIT

## Коротко

Админка уже рабочая и закрывает главные задачи: обновить матчи, добавить матч, выставить результат, исправить результат, управлять турнирами и выдать титул.

Перед UX polish лучше не менять логику. Сначала стоит сделать админку спокойнее визуально: яснее разделить обычные действия, технические блоки и опасные действия.

## Что сейчас удобно

- Админка разделена на понятные страницы: матчи, турниры, пользователи.
- Вверху есть локальная навигация между разделами админки.
- На странице матчей задачи идут примерно в правильном порядке: обновление, добавление, результаты, редактирование.
- Матчи сгруппированы по месяцам и дням. Это удобно, когда матчей много.
- Для списка ручных матчей есть вложенная группировка по лиге, месяцу и дню.
- Статус автообновления вынесен в отдельный блок.
- Технические детали синка спрятаны в `details`, поэтому они не мешают обычной работе.
- Результат можно быстро внести прямо в строке матча.
- Удаление матча и архивация турнира имеют `confirm`.
- Пользователи показаны простой таблицей без лишних действий.
- В `base.html` уже есть общий CSRF fallback для POST-форм.

## Что перегружено

### Страница матчей

Это самая перегруженная часть админки.

На одной странице сейчас живут сразу:

- обновление матчей из API;
- пересчёт очков;
- перевод названий команд;
- статус автообновления;
- техническая история синка;
- добавление ручного матча;
- внесение результата;
- исправление результата;
- редактирование ручных матчей;
- удаление ручных матчей.

Из-за этого админ не всегда понимает, где ежедневная работа, а где редкие технические действия.

### Блок обновления матчей

Три кнопки выглядят почти одинаково, но риск у них разный:

- обновить матчи из API;
- пересчитать очки;
- перевести названия команд.

Пересчёт и перевод выглядят как обычные действия, хотя они массово меняют данные.

### Блок статуса синка

Основной статус полезный, но внутри технических деталей много полей на английском: `Sync run id`, `Status`, `Started`, `Finished`, `Inserted`, `Updated`, `Errors`.

Для разработчика это нормально. Для обычного админа это шум.

### Редактирование ручных матчей

В каждой карточке сразу видны все поля редактирования:

- две команды;
- дата;
- время;
- дедлайн дата;
- дедлайн время;
- сохранить;
- удалить.

Если матчей много, блок быстро становится тяжёлым. Лучше показывать сначала краткую строку матча, а поля открывать по кнопке редактирования.

### Турниры

Список турниров простой, но действия стоят рядом:

- архивировать активный турнир;
- активировать архивный турнир;
- удалить архивный турнир.

Для маленького списка это терпимо. При большом списке риск случайного действия выше.

### Пользователи

Страница пользователей сейчас почти не перегружена. Единственный риск: выдача титула выглядит как обычная форма без подтверждения и без пояснения, что титул уже может быть выдан.

## Где опасные действия плохо отделены

### Удаление матча

Удаление матча находится внутри карточки редактирования и удаляет не только матч, но и прогнозы на него.

Есть `confirm`, это хорошо. Но визуально кнопка находится рядом с обычным сохранением. Её стоит отделить сильнее:

- отдельная зона "опасные действия";
- больше отступ сверху;
- короткий текст, что удалятся прогнозы;
- красная кнопка не на всю ширину, если дизайн позволит.

### Пересчёт очков

Кнопка пересчёта очков находится рядом с обновлением матчей. Она массово меняет очки по завершённым матчам.

Нужна более спокойная подача:

- вынести в блок "Техническое обслуживание";
- добавить подтверждение;
- объяснить, что это нужно после исправления результатов или проблем с очками.

### Перевод названий команд

Кнопка перевода названий команд меняет названия матчей массово.

Сейчас она выглядит как обычная синяя кнопка. Её лучше держать рядом с техническими действиями, а не рядом с ежедневным обновлением.

### Исправление результата

Исправление результата пересчитывает очки. Это важное действие, но сейчас оно выглядит почти так же, как первое внесение результата.

Лучше явно разделить:

- "Внести результат" для матчей без результата;
- "Исправить результат" для уже завершённых матчей;
- в исправлении добавить визуальный знак, что очки будут пересчитаны.

### Удаление турнира

Удалить можно только архивный турнир, это хорошая защита в backend.

Но в UI кнопка удаления стоит рядом с активацией. Лучше отделить удаление в конец строки или в отдельную раскрываемую зону.

### Выдача титула

Выдача титула меняет профиль пользователя. Сейчас подтверждения нет.

Это не критично, но лучше добавить подтверждение или промежуточный текст вида: "Проверь пользователя и титул перед выдачей".

## Какие блоки можно упростить

### Верхний блок страницы матчей

Оставить сверху только ежедневное действие:

- обновить матчи из API;
- краткий статус автообновления.

Пересчёт очков и перевод команд перенести ниже в технический блок.

### Статус автообновления

Оставить на виду:

- общий статус;
- когда было последнее обновление;
- сколько матчей обновлено;
- есть ли ошибки.

Техническую таблицу оставить скрытой. Её можно назвать проще: "Детали для диагностики".

### Добавление матча

Форма нормальная, но её можно сделать чуть легче:

- команды оставить первыми;
- дату и время оставить в одной строке;
- дедлайн оставить как "расширенные настройки";
- лигу и турнир не смешивать по смыслу: турнир важнее, лига вторична.

### Внесение результата

Это хороший блок для ежедневной работы. Его лучше держать выше редактирования.

Можно добавить больше контекста в карточку матча:

- дата и время;
- турнир или лига;
- текущий статус, если он есть.

### Исправление результата

Можно оставить свернутым по умолчанию, потому что это не ежедневное действие.

### Редактирование ручных матчей

Сейчас лучше упростить сильнее всего:

- сначала показывать только список матчей;
- поля редактирования раскрывать по кнопке;
- удаление держать отдельно от сохранения.

### Турниры

Можно разделить список на две группы:

- активные;
- архив.

Тогда удаление архивного турнира будет меньше путаться с обычной сменой активности.

### Пользователи

Можно оставить почти как есть.

Мелкое улучшение: в форме выдачи титула сначала выбрать пользователя, потом титул, потом отдельная кнопка с подтверждением.

## Что нельзя трогать

На этапе UX polish лучше не трогать:

- backend-логику пересчёта очков;
- `recalc_match_points` и `recalc_tournament_points`;
- правила дедлайнов и перевод времени в MSK/UTC;
- CSRF-поля в формах;
- `admin_required`;
- POST endpoints и названия `action`, если нет отдельной задачи на backend;
- защиту, которая запрещает удалить активный турнир;
- текущие smoke-сценарии из `docs/SMOKE_CHECKLIST.md`;
- нижнюю навигацию и выбор турнира в `base.html`, если polish касается только админки;
- сервис-воркер и splash screen;
- структуру данных, которую готовят `prepare_admin_matches_data` и `prepare_admin_view_data`;
- маршруты, которые сейчас могут быть привязаны к старой странице `/admin`.

Важно: многие формы на новых страницах всё ещё отправляют действия на `admin.admin` и после действия могут вернуть на `/admin`. Это не надо чинить в первом UX polish, если задача только визуальная. Но это стоит записать как отдельный технический долг.

## Safe polish plan

### Шаг 1. Навести порядок без изменения логики

- Не менять endpoints.
- Не менять имена полей форм.
- Не менять backend.
- Только переставить и переименовать UI-блоки.
- Проверить, что все POST-формы всё ещё отправляют те же данные.

### Шаг 2. Разделить обычные и технические действия

На странице матчей сделать три зоны:

- "Ежедневно": обновить матчи, статус синка.
- "Матчи": добавить матч, внести результат.
- "Обслуживание": пересчёт очков, перевод названий, технические детали синка.

### Шаг 3. Отделить опасные действия

- Удаление матча вынести в отдельную красную зону внутри карточки.
- Удаление турнира отделить от активации.
- Для пересчёта очков и перевода названий добавить подтверждение.
- Для выдачи титула добавить подтверждение.

### Шаг 4. Упростить редактирование ручных матчей

- Сначала показывать компактную строку матча.
- Поля редактирования открывать только по кнопке.
- Не показывать все поля сразу для каждого матча.

### Шаг 5. Проверить мобильный вид

По smoke checklist особенно важно:

- карточки не вылезают за экран;
- кнопки нажимаются удобно;
- аккордеоны открываются и закрываются;
- Save/Сохранить работают;
- админка открывается без 500.

### Шаг 6. Проверить после polish

Минимальный набор:

- открыть `/admin`;
- открыть `/admin/matches`;
- открыть `/admin/tournaments`;
- открыть `/admin/users`;
- обновить матчи из API на тестовом окружении;
- добавить тестовый матч;
- внести результат;
- пересчитать очки;
- проверить мобильный вид.

## First recommended step

Первый шаг: сделать страницу `admin_matches.html` спокойнее, не меняя backend.

Конкретно:

1. Оставить сверху только "Обновить матчи из API" и краткий статус автообновления.
2. Перенести "Пересчитать очки" и "Перевести названия команд" в отдельный блок "Обслуживание".
3. Скрыть техническую историю синка глубже под "Детали для диагностики".
4. Визуально отделить "Удалить матч" от "Сохранить".

Это даст заметный UX polish с низким риском. Логика останется прежней, а админке станет легче доверять.
